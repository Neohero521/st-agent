# v1.11：对着源码逐条校正写入路径

这一版不改 UI，只解决一个要命的问题：**工具看起来成功，用户在酒馆里却看不到效果**。
下面每条都标了 ST 1.19.1 的真实文件与行号，可自行复核。

## 1. 世界书条目

| 项 | 事实 |
| --- | --- |
| 服务端端点 | `POST /api/worldinfo/edit`（`src/endpoints/worldinfo.js:134`）。要求 body `{name, data}` 且 `data.entries` 存在；`writeFileAtomicSync` 整本原子写，没有「单条 upsert」端点 |
| 前端封装 | `saveWorldInfo(name, data, immediately)`（`public/scripts/world-info.js:4177`）；`createWorldInfoEntry`（:4137）；`getFreeWorldEntryUid`（:4395）；`deleteWorldInfoEntry`（:4043）；`deleteWorldInfo`（:4346）；`createNewWorldInfo`（:4448） |
| 条目字段 | 官方模板 `newWorldInfoEntryDefinition`（:4083-4124）。排序字段是 **`order`**、禁用字段是 **`disable`**；深度 `depth`；字符过滤是对象 `characterFilter: {names, tags, isExclude}`（:1279-1295, 1349） |

**修掉的 bug**：v1.9/v1.10 写的是 `insertion_order: 100` 与 `enabled: true`。ST 完全不读这两个键，条目写进去 `order` 是 `undefined`，排序与插入位置全乱。v1.11 换成官方模板，并把旧字段名做兼容映射（`insertion_order → order`、`enabled → !disable`）。

**写完不等于生效**。ST 生成时收集的书单有三处，必须显式激活：

- `global` → `power_user.world_info.globalSelect`（`world-info.js:998` 读取）
- `chat` → `chat_metadata.world_info`
- `character` → 角色卡 `data.extensions.world`

新增 `world.activate {name, scope, value, char}` 覆盖这三档。另加 `world.getEntry`，可直接读回 `order/disable/position/depth` 核对。

## 2. 角色卡

| 项 | 事实 |
| --- | --- |
| 合并端点 | `POST /api/characters/merge-attributes`（`src/endpoints/characters.js:1329`）：`readCharacterData` → `deepMerge` → `processUnsetSentinels` → `TavernCardValidator` → 写回 PNG |
| 删除字段 | 用哨兵 `__@@UNSET@@__`（`characters.js:1244`），不是传 null |
| 单字段端点 | `POST /api/characters/edit-attribute`（:1194）：**字段必须已经存在**，否则 400；只写一个字段，每次都要重写整张 PNG；同时写顶层与 `char.data` |
| 官方写法 | `/char-update`（`public/scripts/slash-commands.js:5283` 起）：顶层字段与 `data[field]` **双写**；tags 转数组；世界书 → `data.extensions.world`；话痨度/收藏/作者注释 → `data.extensions.*` |

**修掉的 bug**：旧 `char.edit` 对每个字段各发一次 `edit-attribute`。改 6 个字段就是 6 次请求 + 6 次 PNG 重写；`extensions.world`、`depth_prompt`、`unset` 根本写不了（字段不存在直接 400）。V2 卡读的是 `data`，只写顶层会「看起来没改」。

v1.11 改成一次 `merge-attributes`，顶层与 `data` 双写，支持 `cardName / world / talkativeness / depth_prompt / extensions / unset[]`。同时把「角色选择器」和「卡名字段」拆开——以前传 `name` 会顺带改卡名。

## 3. 酒馆助手脚本（JS-Slash-Runner 4.12）

结构（`src/type/scripts.ts:16-31`）：

```
{ type:'script', enabled, name, id, content, info, button:{enabled, buttons[]}, data, export_with }
```

写入（`src/function/script.ts:13-22`）：`getScriptTrees({type})` / `replaceScriptTrees(trees, {type})` / `updateScriptTreesWith(updater, {type})`，`type ∈ global | preset | character`；持久化由 `store/scripts.ts` 的 computed 声明 settings store。

**修掉的四个 bug**（旧 `script.set` 实际是坏的）：

1. 字段写 `code`，真名是 **`content`** → `ScriptTree.parse` 丢弃未知键，脚本存进去是空的；
2. 写 `buttons: []`，真名是 **`button: {enabled, buttons}`**；
3. 用 `stripId` 重建整棵树 → **丢掉 `id`**，每次保存都生成新 uuid，JSR 里 iframe runtime 与按钮绑定全断；
4. `getScriptTrees()` / `replaceScriptTrees(trees)` **不传 `{type}`**，而后者是必填参数——仓库版会直接 TypeError。

v1.11 全部修正，并新增 `script.get`（读回确认）与 `script.delete`（支持文件夹内脚本）。

## 4. 正则

官方正则扩展 `public/scripts/extensions/regex/engine.js:113,144-145`：读 `extension_settings.regex`，写完 `saveSettingsDebounced()`。字段 `id / scriptName / findRegex / replaceString / placement[] / disabled / markdownOnly / promptOnly / runOnEdit / substituteRegex`。

核对结论：**原实现是对的**，不需要改。v1.11 只补了 `regex.delete`。另注意 ST 还有 `extension_settings.regex_presets`（正则预设，`regex/index.js:133`），本轮未做。

## 5. 预设

`POST /api/presets/save`（`src/endpoints/presets.js:42`），body `{name, apiId, preset}`；`/delete`（:60）、`/restore`（:83）。`apiId` 决定落哪个目录、用什么扩展名（`getPresetSettingsByAPI`）。

核对结论：**原实现正确**（写文件是原子的）。保存后前端预设列表要重新拉一次才会出现，靠 `preset.load` 刷新。
