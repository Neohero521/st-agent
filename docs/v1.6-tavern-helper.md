# v1.6 · 酒馆助手（TavernHelper）直连层

工具数 104 → 116。这一层不再模拟酒馆，而是**借用酒馆助手（JS-Slash-Runner 4.x）已经包好的高层 API**，去做原生扩展根本够不到的事情。

## 为什么非得走酒馆助手

三件事酒馆没暴露给前端扩展：

1. **预设提示词的读写**。`PromptManager` 是 `scripts/PromptManager.js` 里的模块，`getContext()` 不返回它；UI 之外没有任何入口。酒馆助手把它包成了 `getPreset / setPreset / updatePresetWith / replacePreset`，其中 `getPreset('in_use')` 直接给出当前生效预设的全部提示词结构。
2. **世界书的绑定关系**。角色主世界书、附加世界书（`world_info.charLore`）、聊天级世界书（`chat_metadata` 上的键）、以及世界书全局设置（扫描深度 / 预算 / 递归 / 大小写），原生扩展只能碰条目，碰不到这些关系。
3. **楼层重排与渲染态文本**。`rotateChatMessages` 在酒馆里是内部函数；把文本跑成"屏幕上最终显示的样子"（宏 + 变量 + 正则 + markdown）也只有 `messageFormatting`，同样不在 context 里。

没装酒馆助手时，这 12 个工具仍在列表里，但调用会明确报「没找到 TavernHelper」，不会静默失效。

## 装酒馆助手的两个硬坑（本轮实测）

**坑一：不能放 `extensions/third-party/`**

`/api/extensions/discover` 只读 `data/<user>/extensions/` 的**直接子目录**（`src/endpoints/extensions.js:511`），third-party 下的东西虽然也会被列成 `third-party/xxx`，但那是针对 `public/scripts/extensions/` 的规则。放错位置时它在面板里"看起来装了"，脚本却加载不到。

正确位置：

```
data/<用户名>/extensions/JS-Slash-Runner/
├── manifest.json      ← js: dist/index.js
├── dist/              ← index.js / index.css
├── lib/               ← 必须有！见坑二
└── i18n/
```

**坑二：`lib/` 目录不能漏**

`dist/index.js` 第一行是 `import{...}from"../../../../../scripts/utils.js"` 这类静态导入，其中一条是 `from"../lib/jsoneditor.js"` —— 相对 `dist/` 的上一层。只复制 `dist` 的结果是：

- 控制台刷一串 404，但没有一条指向真正的原因
- `import()` 直接抛 `Failed to fetch dynamically imported module`
- `globalThis.TavernHelper` 永远是 `undefined`，`YAML` / `z` 也都没有（说明整个模块压根没执行到 ready 回调）

排查方法：在控制台跑 `await import('/scripts/extensions/third-party/JS-Slash-Runner/dist/index.js')`，报错会指到缺失的模块；补上 `lib/` 后 `TavernHelper` 立刻出现（实测 4.12.2 暴露 160 个方法）。

## 12 个工具

| 工具 | 作用 |
| --- | --- |
| `th.status` | 酒馆助手版本、ST 版本、方法总数、按预设/世界书/楼层/变量/生成/正则/导入/扩展分组的能力计数 |
| `preset.prompts` | 列当前预设全部提示词：id、显示名、启停、role、插入位置（`in_chat d4 o100` 或 `relative`）、字符数、正文预览 |
| `preset.promptEdit` | 改单条：正文 / 启停 / role / 显示名 / 位置（type+depth+order），返回 before→after 对照 |
| `preset.promptAdd` | 加一条（默认 in_chat 深度 4 顺序 100，id 自动 uuid） |
| `preset.promptRemove` | 删一条（启用区与未启用区一起清） |
| `preset.promptOrder` | 批量写 `orders`（id→order）、`enabled`（id→bool）、`sequence`（相对位置重排） |
| `lore.bind` | 角色主/附加世界书、聊天级世界书（设/解除/没有就建） |
| `lore.settings` | 世界书全局设置读写 |
| `msg.rotate` | 把 `[middle,end)` 段整体搬到 `begin` 前 |
| `msg.render` | 宏 + 变量展开后的纯文本，再叠正则与 markdown 得到最终显示态 |
| `import.raw` | 从 JSON / JSONL 字符串直接导入角色卡、世界书、预设、正则、聊天档 |
| `gen.models` | 当前模型/源/反代名；给 `apiurl` 则拉该端点模型列表 |

## 实测记录

**预设提示词全链路**（当前预设 Default，12 条）

```
preset.promptAdd {prompt_name:"v16 测试提示词", content:"TEST-V16", depth:4, order:50}
→ added: {id:"4084ce38-…", position:"in_chat d4 o50", chars:8}
preset.promptEdit {id:"4084ce38-…", content:"TEST-V16-EDITED", order:60}
→ before: in_chat d4 o50 / chars 8    after: in_chat d4 o60 / chars 15
preset.promptOrder {orders:{id:70}, enabled:{id:false}}
→ changed: 2
preset.promptRemove {id}
→ removed: {enabled:false, position:"in_chat d4 o70"}
```

`updatePresetWith` 是传函数做深改，改完立刻落盘（重新读 `preset.prompts` 仍然是新值）。

**楼层重排**：原 `[你好。(char), A1, B2, C3]` → `msg.rotate {begin:0, middle:1, end:3}` → `[A1, B2, 你好。, C3]`，与 `rotateChatMessages` 的语义一致（把 `[1,3)` 移到 0 号位之前）。

**渲染态**：`msg.render {text:"{{char}} 在 {{user}} 面前"}` → `expanded: "SillyTavern System 在 User 面前"`。注意**只调 `formatAsDisplayedMessage` 不会展开宏**——它只做 `messageFormatting`（正则 + markdown + 转义）。所以工具里先走 `substituteParams`（和生成时同一套宏引擎），再交给显示层。

**世界书全局设置**（实测返回的真实字段）

```
selected_global_lorebooks: ["Eldoria"], scan_depth: 2, context_percentage: 100,
budget_cap: 0, min_activations: 0, max_depth: 0, max_recursion_steps: 0,
insertion_strategy: "character_first", recursive: true, case_sensitive: false
```

**原始导入**：`import.raw {kind:"worldbook", name:"v16RawTest"}` 后 `worlds/v16RawTest.json` 立刻落盘。但 `world.list` 读的是酒馆内存里的 `world_names`，不会自己刷新——所以工具返回里写了提示，重进一次世界书面板才会看到新名字。

## 和「酒馆助手」自己的关系

这层不是替代酒馆助手，而是把它的能力暴露给 Agent 的自主循环。酒馆助手本身是给脚本作者用的（写 JS 脚本跑在聊天里），它没有"理解用户意图 → 自己决定改哪条提示词"的部分；ST Agent 有。两者装在一起才完整：**ST Agent 出脑和手，酒馆助手出底层 API**。
