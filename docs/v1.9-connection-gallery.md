# v1.9 · 连接层、图库与资产搬运

前面八版有个共同空缺：Agent 能改角色卡、世界书、聊天、设置，却**不知道自己现在接的是哪个模型、这个 key 到底配没配、这个端点能生成什么**。这一版补的是「自我认知」和「资产搬运」。

工具数 **139 → 154**（15 个新工具，全部在 `adv-tools-v19.js`）。

## 一、连接层（5 个）

| 工具 | 做什么 | 走哪 |
|---|---|---|
| `api.state` | 读 main_api / chat_completion_source / 正在用的模型 / 端点 / 上下文与 token 上限 / 当前预设 / 已配置密钥 | `chatCompletionSettings` + `/api/settings/get` + `/api/secrets/read` |
| `api.models` | 拉当前 source 的可用模型清单，**同时就是一次真实连通性测试** | `/api/backends/chat-completions/status` |
| `api.key` | 写入/更换某个后端密钥（不回显） | `/api/secrets/write` |
| `api.secrets` | 列出已配置密钥（服务端脱敏值 + label + active） | `/api/secrets/read` |
| `api.switch` | 切 main_api / source / 模型 | `oai_settings` + `saveSettingsDebounced`，main_api 写盘 |

**为什么走两套路径**：`source` 与 `model` 改前端 `chatCompletionSettings` 内存再 `saveSettingsDebounced()`，**立即生效**，不用刷新；`main_api` 是模块级变量（`st-context.js:200` 只暴露读引用），只能写 `settings.json` 再靠刷新页面切过去，所以工具会返回 `needs_reload: true` 明确告知。

**`api.models` 不是普通的"列模型"**：它把 `oai_settings` 里 16 个与端点相关的字段（`reverse_proxy` / `custom_url` / `azure_*` / `claude_endpoint` / `vertexai_*` …）整组拷进 `/status` 的请求体。所以：

- 能列出模型 = 密钥有效 + 端点可达（这就是酒馆「连接」按钮点的那个接口）
- 返回 `error: true` 且列表为空 = 该 source 没配 key、端点不通，或这个 source 本来就不提供模型列表（kobold / textgenerationwebui 走的是另一条路）

**密钥读出边界**：只用 `/api/secrets/read`（返回 `getMaskedValue()` 处理过的值，形如 `sk-abc…`）。`/api/secrets/view` 需要 `config.yaml` 的 `allowKeysExposure: true`（默认 false），`secrets/settings` 只回一个布尔值——所以**任何工具都不会把明文密钥带给模型**。

## 二、图库（5 个）

酒馆 1.13+ 有 `src/endpoints/image-metadata.js`，是一套独立于真实文件系统的**图片元数据索引**（`version` + `images{}` + `folders[]`，落在用户目录的 metadata 文件里）。

| 工具 | 做什么 |
|---|---|
| `img.index` | 总图数 / 文件夹与各自归了几张 / 打了标签几张 + 抽样路径 |
| `img.folders` | 列文件夹（id / name / thumbnailFile） |
| `img.folderCreate` | 新建文件夹 |
| `img.assign` | 批量把图片路径归入/移出文件夹（`action: assign / unassign`） |
| `img.cleanup` | 清「文件早就不在了」的孤立元数据条目（不删真实图片） |

**实测**：测试环境索引里有 23 张图（全是 `backgrounds/*`），0 个文件夹、0 张打标。建 `v19test` → assign 一张 → `folders` 立刻能读回 → 清理后复原，测试残留已删干净。

## 三、资产搬运（4 个）

| 工具 | 做什么 | 走哪 |
|---|---|---|
| `file.upload` | base64 写入酒馆文件区，返回可引用的路径 | `/api/files/upload` |
| `file.delete` | 删文件区里的文件（限 `/user/files/…`，需 `confirm`） | `/api/files/delete` |
| `preset.restore` | 取出厂预设原样内容（只读，不覆盖现有） | `/api/presets/restore` |
| `theme.save` | 把整套主题变量落盘成 `themes/<name>.json` | `/api/themes/save` |
| `translate.run` | 用酒馆内置翻译翻一段文本（不烧聊天额度） | `/api/translate/{provider}` |

**这一版踩到的真实坑**

- `/api/files/upload` 返回的路径是 **`/user/files/…`**（单数 `user`，来自 `clientRelativePath`），不是 `/users/files/…`。第一版文案写错，已改。`file.delete` 的前缀校验也按这个前缀来。
- `/api/translate/google` 在受限网络（含本测试机）会直接 500：`Translator` 类拉 Google 端点失败，服务端只回 `Internal Server Error`。**换 `bing` 立刻可用**（实测 `hello world` → `你好，世界`）。所以 `translate.run` 的说明里写明"google 500 就换 bing"。
- `/api/presets/restore` 名字听起来像"恢复"，实际**只把出厂预设的内容返回**（`{isDefault, preset}`），不落盘。想真恢复必须把它整份喂给 `preset.save`——工具的输出里直接写了这句。
- `/api/image-metadata/cleanup` 没有预演模式，调用即执行；所以第一版的 `dryRun` 参数是假参数，已删掉，避免给人"可以先试"的错觉。
- `api.state` 第一版把 `getChatCompletionModel()` 的结果直接叫 `model`，但测试环境 `main_api: koboldhorde` 时它仍然返回 `gpt-4-turbo`（那是「聊天补全」页里存的模型，此刻根本没在用）。已改名为 `chat_completion_model` 并在 hint 里说清"只有 main_api 为 openai 时才真正生效"。

## 四、这一版明确没做的

- **文生图 / 语音 / 图像打标**（`/api/openai/generate-image`、`/api/speech/*`、`/api/caption`）：都要消耗额度或额外密钥，且和"改酒馆内部数据"不是一类需求，留给用户自己在 UI 里点。
- **`/api/assets/*`**：那是把远端 URL 抓进 `data/assets` 的迁移工具，路径规则和 `files` 不同（`assets/get` 还带一套 CBOR 清单），价值低、坑多，跳过。
- **密钥明文读取**：见上，默认关闭就不硬开。
