# v1.7：群聊整组管理、角色卡内嵌世界书、酒馆体检

工具数 116 → 125（`adv-tools-v17.js`，9 个）。这一版补的是前面六版一直绕开的三块地方：
群聊的写操作、角色卡里塞着的 `character_book`、以及「我的酒馆到底哪里在变胖」。

## 一、群聊：从只读变成全栈

v1.2 只做了 `group.list` / `group.activate`，建群改成员还是得回 UI 手点。v1.7 补齐：

| 工具 | 落到哪个端点 | 说明 |
| --- | --- | --- |
| `group.all` | `POST /api/groups/all` | 比 `group.list` 多给聊天档数、体积（服务端算好的 `chat_size`）、最后聊天时间 |
| `group.info` | 同上 + 内存角色表 | 成员明细：头像 / 角色名 / 是否被禁用，外加 join 前后缀与 `auto_mode_delay` |
| `group.create` | `POST /api/groups/create` | 服务端自己生成 `id = Date.now()`；会先校验头像是否真在角色列表里 |
| `group.edit` | `POST /api/groups/edit` | 改名 / 整体换成员 / `add` / `remove` / 激活策略 / 允许自答 / 生成模式 |
| `group.delete` | `POST /api/groups/delete` | 连该群名下的 `groupChats/*.jsonl` 一起删 |

**两个关键点**

1. `/api/groups/edit` 是**全量覆写整份 group JSON**。只发局部字段会静默丢掉 `chats`、`fav`、`disabled_members` 等字段——所以实现是「先 `all` 取到原对象 → 改 → 整份回传」，任何路径都不手拼对象。
2. `members` 存的是**角色头像文件名**（`AgentTest.png`），不是显示名。工具接受头像；传了不在角色表里的头像会直接报错，不去猜。

实测（`v17测试群`）：

- `group.create` → `id 1795740186617`，`members 2`，`chats 1`（建群时服务端自动建了一档群聊），`activation_strategy 1`
- `group.edit` 改名 + `add` 同一成员 → `members` 仍 2（已做 `Set` 去重），`before` / `after` 双份返回
- `group.edit` `remove` → `members 2 → 1`
- `group.delete` → `group.all` 回到 `count 0`，测试群的文件已消失

## 二、角色卡内嵌世界书

角色卡除了 `data.extensions.world`（绑的独立世界书），还能自己塞一本 `data.character_book`（"character book" / 卡内嵌书）。v1.4 的 `char.export` 只能整卡导出，拆书还得手工。

- `char.book`：读条目数、书名、前 N 条的 `comment` / `keys` / `enabled` / `insertion_order` / 字符数，并顺手告诉你这张卡当前绑的独立世界书是谁
- `char.bookExtract`：把内嵌书抽成**独立世界书**，原名存在时默认拒绝，`overwrite: true` 才覆盖

**别自己映射字段。** `character_book.entries[]` 和 `worldinfo.entries{}` 的差异不是简单的 key/value：`enabled ↔ disable`、`insertion_order` 名字一样但语义挂在 `order`、`extensions.position` 要摊平成 `position` 数字、`secondary_keys ↔ keysecondary`、`case_sensitive` 在两边默认值相反。酒馆前端本来就有 `convertCharacterBook()`（`public/scripts/world-info.js:5617`，是 `export` 的），工具直接 `await import('/scripts/world-info.js')` 复用它。

反向的 `convertWorldInfoToCharacterBook()` 只在服务端 `src/endpoints/characters.js:663` 内部定义、**没有导出**，所以「独立世界书写回卡内嵌」这一版没做，等上游导出再说。

实测（Seraphina，内嵌书 `Eldoria`，4 条）：

```
char.book  → has_book true, book_name "Eldoria", entries 4, linked_world "Eldoria"
              preview[0] = keys [eldoria, wood, forest, magical forest], 1551 字符
char.bookExtract world_name "v17抽书测试"
           → ok true, entries 4, 落盘 worlds/v17抽书测试.json 23713 字节
              entries[0].key 仍是 [eldoria, wood, forest, ...]，comment 保留
```

原卡的 `character_book` 未被改动（抽取只写新文件）。

## 三、酒馆体检

`audit.run` 一次回答「哪里在变胖」，全部基于真实端点而不是估算：

- 角色卡 × 聊天档：逐卡 `GET /api/characters/chats?avatar=…&metadata=true`，累加 `mes_count`
- 世界书：`loadWorldInfo` 逐本统计条目数、**全禁用**条目、constant 条目、**没写 key 的非 constant 条目（永远不会被触发）**、主键与次键都填了的条目
- 群聊：`/api/groups/all` 的体积与档数
- 最近聊天：`POST /api/chats/recent`（`max` 用 `chatSample` 控制，默认 200），取最大 5 档
- 正则：`extension_settings.regex` 条数

输出里 `advice` 是把它翻成人话的部分，例如：

- 「2 张卡没有任何聊天记录（想清磁盘可从它们下手）：AgentTest、Seraphina」
- 「世界书里有非 constant 条目没写 key（永远不会被触发）：Eldoria×2」
- 「最大的一档聊天有 240 楼，上下文和加载都会变慢」

实测（测试环境 2 卡 1 本世界书 0 群聊）：

```
summary: characters 2 / characters_without_chat 2 / worldbooks 1 / worldbook_entries 5
         groups 0 / chat_files 0 / messages_estimate 0 / regex_scripts 0
characters[1]: Seraphina, chats 0, world "Eldoria", embedded_book 4
```

## 四、扩展自维护：一个必须堵的坑

`ext.maintain {action:'update'|'reinstall', id}` 先读 `getExtensionInstallationInfo()`（内部走 `POST /api/extensions/version`，字段是 `remote_url` / `current_commit_hash` / `current_branch_name` / `is_up_to_date`），**先判断 `remote_url` 是不是 http(s)**：

- 不是 → 直接回 `reason: 'not_a_git_repo'`，不调 API

原因很硬：

- `POST /api/extensions/update` 的实现就是 `git.checkIsRepo` + `git.pull`。手动 `cp` 进扩展目录的扩展不是 git 仓库，必然 500（日志：`Directory is not a Git repository at data/default-user/extensions/JS-Slash-Runner`）。第一版就是这么 500 的。
- `reinstallExtension` 更危险：源码顺序是 `uninstallExtension()` → `installExtension(status.remote_url)`。非 git 扩展的 `remote_url` 是空字符串 —— **先删除、再用空 URL 装回 = 扩展直接没了**。所以非 git 环境一律拒绝 reinstall。

实测（手动安装的 JS-Slash-Runner 4.12.2）：

```
update    → ok false, reason not_a_git_repo, 提示手动覆盖或用仓库地址重装
reinstall → ok false, reason not_a_git_repo, 明确说明「删完装不回来」故拒绝
```

对 git 安装的扩展（用 URL 装进 `extensions/` 的那种）两个动作都会正常走通，返回 `http`、`message`、`current_commit_hash` 前 7 位、`branch`、`remote`。
